### Untraced and unresolved items

- **Proof type per operation: not in unit's section.** The brief described the Opcodes section as carrying each operation's proof type, but the staged table has only Operation / Opcode / Description columns, so the pairing was not traced against this section. The first pass observed that the pairing comes from one source in code (`ProvableOperation::Proof`) used consistently by `op_proof.rs:33-47,60-66`, `op.rs:180-196` and `codec.rs:29-62`, and that the existing test `sample_proof_matches_the_kind_each_op_requires` passes. Not a finding.
- **`codec.rs` has no opcode dispatch at this ref.** It holds only `minimum_signed_transaction_size`, an exhaustive match over the closed `OpRef` enum, so there is no unknown-code path in that file to trace. Transaction-level dispatch is `Ops::decode` → `TxBoundedVec::decode` → `Op::decode` in `tx_list/ops.rs:180-189`, outside the unit; the trace reaches it only through rows OPC-18 and the rtx/rstx tests.
- **Observations the first pass parked for other briefs, not findings here:** (a) framing: `op.rs:101-105` drops bytes trailing the payload when a standalone `Op` is bincode-deserialised, whereas `Ops` rejects trailing bytes (`tx_list/ops.rs:241-248`); no production type bincode-deserialises a standalone `Op`, and this is Transaction Encoding, not the opcode table. (b) Op-ID domain separation: `op.rs:29-37` with `mod.rs:31-32` leave the opcode out of the `op_id` preimage and all six `OpId` implementors share the tag `OPERATION_ID_V1`; LeaderClaim and ClaimPowReward payloads are both three 32-byte fields. Whether that matches the op-ID definition belongs to the Transfer / Leader / PoW briefs. (c) Doc drift: `op.rs:57` links a nonexistent `decode_op`, `op.rs:73` a nonexistent `OpInternal`, and `mod.rs:45-46` lists four `OpId` implementors where ChannelTransfer and ClaimPowReward also implement it.
- **Toolchain and ref deltas.** The brief named rustc 1.99.0 and commit `1da2d9d6…`; the clone pins 1.98.1 and resolves `0.3.0` to `f76be2dd…`. Both passes ran on what the clone provides. Absence of a run on the brief's exact toolchain or commit was never treated as proof of a defect.
- **Lanes not run.** No Docker, live nodes or remote CI were needed for this unit; every requirement was settled by a local test run. No row is unresolved.

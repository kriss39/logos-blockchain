### contradicts-spec (proven violation)

#### Finding 1 (F-c4b77e7b) — Ledger derives the priority tip by narrowing the i128 transaction balance to u64 with an unchecked `as` cast, so a balance above u64::MAX wraps modulo 2^64 and the transaction is accepted instead of rejected — **confirmed**, medium severity, high confidence

The specification's Validation step 3 says `tx_priority_tip = checked_uint64(tx_balance - tx_mandatory_fee)`, and its Arithmetic section says a Mantle Transaction is invalid if any result cannot be represented in its integer type: results must never silently wrap around or saturate. `LedgerState::try_apply_transaction` in `ledger/src/lib.rs` checks `balance < total_gas_cost` on the i128 balance and then computes `fee_tip = GasCost::from(balance as Value).checked_sub(fee_burned)`. The `as Value` cast truncates the i128 balance to its low 64 bits before the checked subtraction, so the only check that remains is on the truncated value. A transaction whose balance (sum of TRANSFER inputs minus outputs across its operations) exceeds u64::MAX, which the spec declares invalid, is accepted whenever the truncated value still covers the fee, and the tip is recorded as the truncated remainder: 2^64 base units of excess balance disappear from the accounting. A spec-conforming validator rejects such a block while this implementation accepts it.

What the finding does not establish: no fund loss on a live network is shown. The per-operation input sum is a checked u64 sum (`Inputs::amount`), so triggering this needs at least two TRANSFER operations in one transaction and a spendable set whose total value exceeds 2^64 base units; it is unreachable while total supply stays below that. Mempool admission and the wallet's fee estimate in core are not affected. The code line is in `ledger/src/lib.rs`, outside the files the brief listed, because that is where this section's fee check and tip computation live.

- Locations: `ledger/src/lib.rs:510` (`balance < total_gas_cost` check on the i128 balance, matches `assert tx_mandatory_fee <= tx_balance`), `ledger/src/lib.rs:515` (`GasCost::from(balance as Value).checked_sub(fee_burned)`, the unchecked narrowing), `ledger/src/lib.rs:102` (`Balance = i128`), `ledger/src/lib.rs:497-500` (mandatory fee, checked, conforming).
- Repro: `cargo test --locked -p logos-blockchain-ledger --all-features -- proof_20261022t231401_aae375_1` → observed (exit 101): `test proof_20261022t231401_aae375_1::tip_is_checked_uint64_of_balance_minus_mandatory_fee ... The recorded tip equals the low 64 bits of the balance minus the fee; the missing 2^64 is exactly one wrap. `as` wraps identically in release, and the workspace release profile does not enable overflow-checks.
- Second pass: confirmed — independently ran the same command from the review checkout (HEAD `b4790076e3532a6eddac5ef057160fbdd1e3b398`, whose only changes relative to tag 0.3.0 are the first-pass test and its cfg(test) registration): exit 101, the named test failing at its assertion because `try_apply_transaction` accepted balance 36893488147419103228 with mandatory fee 1507 and recorded tip 18446744073709550105. Supporting checks: all 103 core `mantle::transactions::` tests and all five ledger `test_fee` tests passed. No source files were edited.
- Merge-pass adjudication: not applicable; the finding was raised by the first pass and its status is set by the second pass's verdict.
- Disposition: not applicable; the passes agree.
- Fix: in `ledger/src/lib.rs` `try_apply_transaction`, compute the tip in i128 and convert with a fallible conversion, failing the transaction on overflow as `checked_uint64` does: `let tip = balance.checked_sub(Balance::from(total_gas_cost.into_inner())).ok_or(LedgerError::BalanceOverflow)?; let fee_tip = GasCost::from(Value::try_from(tip).map_err(|_| LedgerError::BalanceOverflow)?);` (keep the `balance < total_gas_cost` check before it, or fold it into the same conversion since a negative tip also fails `try_from`). Apply the same treatment anywhere else an i128 `Balance` is narrowed with `as`. The proof test `tip_is_checked_uint64_of_balance_minus_mandatory_fee` then passes.
